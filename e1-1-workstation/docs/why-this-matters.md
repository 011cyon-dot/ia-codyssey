# 이걸 왜 하나 — AI 과정에서 터미널·Docker·Git 을 먼저 배우는 이유

실습하는 동안에는 "AI 과정인데 왜 폴더 만들고 컨테이너 켜고 끄는 걸 하지?" 싶었다.
끝나고 정리해 보니, AI 를 **쓰는** 쪽이 아니라 **만들고 돌리는** 쪽의 바닥이 이것이었다.

## 오늘 배운 것 → AI 일에서 쓰이는 곳

| 오늘 배운 것 | AI 일에서는 |
|---|---|
| 터미널 | AI 모델 학습·실행은 거의 다 터미널에서 한다. 코딩을 도와주는 AI 도구(Claude Code 등)도 터미널에서 돌아간다 |
| 권한 (`chmod`) | API 키 같은 비밀 파일을 나만 읽게(`600`) 막는다 |
| Docker 이미지·컨테이너 | AI 프로그램은 파이썬 버전·라이브러리·GPU 설정이 조금만 달라도 안 돌아간다. 그래서 통째로 이미지에 담아 어디서든 똑같이 돌린다 |
| Dockerfile | "무엇을 깔고 무엇을 넣을지"를 글로 남겨서, 남이 그대로 다시 만들 수 있다 |
| 포트 매핑 | AI 모델을 웹 서버로 띄워 두고, 앱이 `주소:포트` 로 질문을 보낸다 |
| 바인드 마운트 | 코드를 고치면 컨테이너를 다시 만들지 않고 바로 확인한다 |
| 볼륨 | 모델 파일·데이터(수 GB)를 컨테이너를 지워도 남게 따로 보관한다 |
| Git/GitHub | 코드와 실험 기록을 남긴다. AI 가 짠 코드도 여기서 검토하고, 틀리면 되돌린다 |

## 한 줄로

**"내 컴퓨터에서만 되는" AI 는 쓸 수 없다.** 어느 컴퓨터에서든 똑같이 돌아가게 하는 바탕이 컨테이너·포트·볼륨·Git 이다.

## 내 경우에 대보면

- 내가 쓰는 업무 앱도 내 컴퓨터에서 포트를 열어 떠 있고, 화면은 따로 있다. 오늘 `-p 8080:80` 으로 한 것과 같은 구조다.
- 고친 코드를 GitHub 에 올리면 자동으로 배포된다. 오늘 `git push` 한 것의 다음 단계다.

## 느낀점

처음엔 AI 과정에서 왜 터미널과 Docker 부터 하나 싶었다.
해 보니 AI 프로그램도 결국 어느 컴퓨터에서든 똑같이 돌아가야 쓸 수 있고, 그 바탕이 컨테이너·포트·볼륨·Git 이었다.
내가 이미 쓰는 AI 도구들도 이 위에서 돌아간다는 걸 알게 됐다.
